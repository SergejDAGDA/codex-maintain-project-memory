## Sources of truth

This table maps **stable evidence roles to their authoritative sources**. Describe what
each source can establish, not the project's transient current results. Do not
copy passing test results, failing tests, current bugs, task completion, blockers or next
steps from `STATUS.md` into these rows. Leave the `Approved intent` source
as `TBD` unless a concrete user approval or explicitly governing approved source
is identified; code, tests and descriptive project files alone do not prove approval.

| Evidence role | Canonical source | What it establishes |
|---|---|---|
| Approved intent | TBD | Explicitly approved goals, scope, constraints, and decisions |
| Implemented state | Code, tests, configuration, maintained docs, and verified runtime evidence | What currently exists or behaves as observed; not approval by itself |
| Current coordination state | `STATUS.md` and an active `HANDOFF.md` | Current outcome, risks, next pending action, and unfinished transfer context |
| Decision index | `DECISIONS.md` | Attributed decision records; not self-validating without provenance |
| Historical checkpoints | `SESSION_LOG.md` | What earlier checkpoints recorded |
| Operational/runtime authority | Project-specific current source when applicable | Current external operational state; project memory points to it but does not replace it |

External sources must be marked as non-portable unless they are intentionally included in the repository. Staging, deployment, mirror, or backup copies of project memory are non-canonical unless explicitly declared as a separate project root.
